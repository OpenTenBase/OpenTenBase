# OpenTenBase 核心架构术语与新手指南

欢迎来到 OpenTenBase 开源社区！本指南旨在帮助新开发者快速理解 OpenTenBase 的分布式架构、核心组件职责及基础运维操作。

---

## 📚 核心术语表 (Architecture Glossary)

| 序号 | 核心术语 | 英文简称 | 新手通俗解释与职责描述 | 状态属性 |
| :---: | :--- | :--- | :--- | :--- |
| **1** | **协调节点** | **CN** *(Coordinator)* | **项目的“大脑与前台”**。负责接收客户端 SQL 请求，解析 SQL 并生成分布式执行计划，把子任务路由给 DN 执行，最后汇总结果返回给用户。 | 无状态（支持横向扩展） |
| **2** | **数据节点** | **DN** *(DataNode)* | **项目的“仓库与工人”**。实际存储数据分片（Shard）的地方，基于 PostgreSQL 内核，负责执行 CN 分发的局部 SQL 算子并返回结果。 | 有状态（需主备高可用） |
| **3** | **全局事务管理器** | **GTM** *(Global Transaction Manager)* | **项目的“裁判与全局时钟”**。负责发放全局事务 ID (GXID) 和全局快照，掌控全局两阶段提交 (2PC)，确保分布式事务的 ACID 特性。 | 有状态（主备高可用） |
| **4** | **分布式模式** | **Distributed Mode** | **多机并行架构**。数据通过 Hash 或 Range 切片散落在多个 DN 上，适合海量数据和高并发分析/写入场景。 | 架构类型 |
| **5** | **集中式模式** | **Centralized Mode** | **单机/主备模式**。所有数据存储在单一节点上，架构简单，适合小数据量或传统单机数据库迁移场景。 | 架构类型 |
| **6** | **节点组** | **Node Group** | **DN 的逻辑集合**。用于实现多租户隔离或数据分片管理。创建表时可以指定存储在哪个 Node Group 中。 | 逻辑概念 |
| **7** | **运维管控工具** | **`opentenbase_ctl`** | **集群的“指挥控制台”**。用于一键部署集群、启停节点、查看状态、动态扩缩容及参数配置的 CLI 工具。 | 运维工具 |
| **8** | **全局事务 ID** | **GXID** | 在分布式环境下唯一标识一个事务的递增 ID，保证不同节点间事务可见性的一致性。 | 事务属性 |
| **9** | **全局系统元数据** | **Global Catalog** | 存储在 CN 上的元数据（如表结构、分布键、节点路由信息），确保所有 CN 对外展现一致的数据库视图。 | 元数据 |
| **10** | **分布表** | **Distributed Table** | 数据根据分布键（Distribution Key）通过 Hash 或 Range 算法打散存储在各个 DN 上的表。 | 数据表类型 |
| **11** | **复制表** | **Replicated Table** | 每个 DN 上都完整保留一份全量数据的表（如字典表/小表），用来加速与大表的本地 Join 查询。 | 数据表类型 |
| **12** | **两阶段提交** | **2PC** | 分布式事务提交协议（Prepare -> Commit），确保跨 DN 写入时要么全部成功，要么全部回滚。 | 事务协议 |
| **13** | **全局统一参数** | **GUC** | OpenTenBase 内核控制配置参数，可在 CN/DN/GTM 间同步配置控制数据库行为。 | 配置参数 |

## 🔄 组件协同与 SQL 数据流转架构关系

在分布式模式下，OpenTenBase 的各个核心组件协同处理一次 SQL 请求的完整流程如下：

```
[ 客户端 / 应用 ] 
      │ 
      │ 1. 发送 SQL (例: SELECT * FROM t_user WHERE id = 100;)
      ▼
┌─────────────┐       2. 申请全局事务 ID (GXID)       ┌─────────────┐
│   CN 节点   │ ─────────────────────────────────► │   GTM 节点  │
│ (请求解析/路由)│ ◄───────────────────────────────── │ (全局事务管理)│
└─────────────┘       3. 返回一致性快照 (Snapshot)    └─────────────┘
      │
      │ 4. 计算 Shard Key，将 SQL 拆解下发到目标 DN
      ├───────────────────────┐
      ▼                       ▼
┌─────────────┐         ┌─────────────┐
│  DN 01 节点 │         │  DN 02 节点 │
│ (存储与计算) │         │ (存储与计算) │
└─────────────┘         └─────────────┘
      │                       │
      └───────────┬───────────┘
                  │ 5. 返回局部查询结果
                  ▼
┌─────────────┐
│   CN 节点   │ ──► 6. 汇总/排序数据并返回给 ──► [ 客户端 / 应用 ]
└─────────────┘
```

## 💡 新手常用实操命令与系统表速查

* **查看当前集群路由与节点状态：**
  在 CN 节点连入数据库（`psql -h 172.20.0.2 -p 11000 -U opentenbase postgres`）后执行：
  ```sql
  SELECT node_name, node_type, node_port, node_host FROM pgxc_node;
  ```
* **查看集群整体运行状态：**
  ```bash
  opentenbase_ctl status -c /data/opentenbase/config.ini
  ```
