OpenTenBase 集群里，谁在算什么？

一条 SQL 进来之后，集群里三个角色各做一件事：CN 负责拆解与协调， DN 负责真正存取数据，GTM 负责给全局事务发号。 这张卡片用一张图说清三者的分工边界。

怎么读这张图

  1. 用户只连 CN（协调节点）。CN 解析 SQL、生成执行计划，把查询拆成片段下发到 DN。
  2. DN 才是放数据的地方。一个集群可以有多个 DN，用户数据按分布键切开，分别存放在不同 DN 上。
  3. GTM 不存业务数据，只负责全局事务：给跨节点事务分配全局事务号（GID）与快照，保证多个 DN 上的一致性。
  4. CN 与 DN 共享同一份 schema，所以 CN 才知道表结构；但表里的行只落在 DN 上。

生活类比

顾客（客户端）只跟服务员（CN）点单；服务员把一桌菜拆成几份，分给不同灶台（DN）去做；收银台（GTM）统一给这一桌开一张总单号，保证结账时几道菜算作同一笔。

类比只帮助建立直觉，不是技术定义：CN 不做数据计算、GTM 不参与查询执行、DN 也不主动对外服务，这些边界以项目文档为准。

常见误解

误解实际情况
CN 里存着表数据CN 只保存元数据与全局对象信息；行数据全部在 DN 上。
GTM 是"主数据库"GTM 只发全局事务号和快照，不存用户表。
连任意节点都一样应用应连接 CN；DN 不对外提供完整的 SQL 入口。
